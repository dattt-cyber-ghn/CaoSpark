S
Scope
Phạm vi kích hoạt

Skill này dùng khi nào?

Đây là yếu tố quan trọng nhất — quyết định AI có tự động dùng Skill hay không. Tương ứng với trường description trong file SKILL.md. Mô tả mơ hồ → Skill không bao giờ chạy.

Map vào SKILL.md
YAML frontmatter: description
Độ dài lý tưởng
1-2 câu, 50-150 ký tự
Ví dụ tốt "Dùng khi user yêu cầu review code Python để tìm lỗi bảo mật, bug logic, hoặc vi phạm style guide PEP8. Trigger với từ khóa: review, audit, code check, security."
P
Persona
Vai trò & đối tượng

Ai làm? Cho ai?

Khai báo "danh tính" của AI khi chạy Skill: chuyên môn, kinh nghiệm, đối tượng phục vụ. Persona càng cụ thể, output càng đúng giọng và đúng chuyên môn.

Map vào SKILL.md
Phần "Role" hoặc "Context" trong markdown body
3 yếu tố cần
Vai trò + Chuyên môn + Đối tượng
Ví dụ tốt "Bạn là senior security engineer 10 năm kinh nghiệm. Đối tượng review là code của junior developer Việt Nam, cần giải thích dễ hiểu kèm ví dụ sửa."
A
Action
Quy trình từng bước

Quy trình thực thi step-by-step

Khác với prompt cơ bản (1 yêu cầu), Skill cần nhiều bước có thứ tự. Liệt kê dưới dạng numbered list. AI sẽ làm theo đúng tuần tự.

Map vào SKILL.md
Phần "Instructions" hoặc "Workflow"
Format chuẩn
Numbered list, mỗi bước 1 động từ rõ ràng
Ví dụ tốt "1. Đọc toàn bộ file. 2. Quét tìm SQL injection, XSS, hardcoded secrets. 3. Kiểm tra error handling. 4. Đề xuất fix kèm code mẫu. 5. Tóm tắt mức độ severity."
R
Rules
Ràng buộc & tiêu chuẩn

Bắt buộc làm / Cấm làm

Tách riêng 2 loại: MUST (định dạng output, độ dài, ngôn ngữ, giọng văn) và MUST NOT (cấm kỵ, sai lầm cần tránh). Đây là điểm phân biệt Skill chuyên nghiệp với prompt nghiệp dư.

Map vào SKILL.md
"Constraints" + "Output format"
Cấu trúc
DO / DON'T list rõ ràng
Ví dụ tốt "MUST: Output bảng Markdown, tiếng Việt, có cột Severity (low/med/high). MUST NOT: Đề xuất rewrite toàn bộ file. Không bịa lỗi không có trong code."
K
Knowledge
Ví dụ & tài nguyên

Đính kèm kiến thức nền

Few-shot examples (input mẫu → output mẫu) giúp AI bắt chước chính xác hơn 10 lần so với mô tả suông. Có thể đính kèm file template, checklist, hoặc reference riêng.

Map vào SKILL.md
"Examples" + thư mục references/
Số lượng đề xuất
2-3 examples đa dạng
Ví dụ tốt "Example 1: Input có SQL injection → Output bảng cảnh báo + code đã fix. Example 2: Input clean → Output xác nhận pass + 2 cải tiến nhỏ."
03 / Cấu trúc thật

File SKILL.md trông thế nào?

SPARK không phải lý thuyết suông. 5 thành phần map 1-1 vào file SKILL.md chuẩn theo agentskills.io — chạy được trên Antigravity, Claude Code, Cursor, Codex CLI.

Một Skill = 1 folder + 1 file

Cấu trúc tối thiểu chỉ cần 1 thư mục tên kebab-case (ví dụ: code-reviewer/) chứa 1 file tên SKILL.md.

File gồm 2 phần:

  • YAML frontmatter giữa hai dấu --- — chứa name và description (bắt buộc)
  • Markdown body — chứa Persona, Action, Rules, Knowledge

Đặt vào 1 trong 2 vị trí:

  • Global: ~/.gemini/antigravity/skills/ — dùng cho mọi project
  • Workspace: .agent/skills/ — chỉ cho project hiện tại
code-reviewer/SKILL.md 
---
name: code-reviewer
description: Review code Python tìm lỗi
  bảo mật, bug logic, vi phạm PEP8.
  Dùng khi user nói "review", "audit",
  "check code".
---

# Code Reviewer Skill

## Persona
Bạn là senior security engineer
10 năm kinh nghiệm Python.

## Workflow
1. Đọc toàn bộ file
2. Quét SQL injection, XSS, secrets
3. Kiểm tra error handling
4. Đề xuất fix kèm ví dụ
5. Tóm tắt severity

## Rules
# MUST
- Output bảng Markdown
- Tiếng Việt
- Có cột Severity

# MUST NOT
- Không rewrite toàn bộ file
- Không bịa lỗi

## Examples
[xem references/examples.md]

⚠ Trường description quyết định tất cả

Đây là điểm 90% người mới làm sai. AI chỉ load Skill khi description khớp với yêu cầu của user. Description tệ → Skill nằm im mãi mãi. Hãy so sánh:

description: "Giúp về code"

AI không biết khi nào nên dùng. Có thể không bao giờ kích hoạt, hoặc kích hoạt sai lúc.

description: "Review code Python tìm lỗi bảo mật, bug logic, vi phạm PEP8. Dùng khi user nói 'review', 'audit', 'check code'."

Có động từ rõ + đối tượng cụ thể (Python) + trigger keywords. AI biết chính xác khi nào load.

BƯỚC 01 / 06 — ĐẶT TÊN

Skill này tên là gì?

Vì sao quan trọng: Tên kebab-case sẽ là cả tên folder lẫn trường name trong YAML. Sai chuẩn naming → Antigravity không load.
Theo nghề
  • Dev: code-reviewer / pr-description-writer / test-generator
  • Marketing: facebook-caption / seo-blog-writer / cold-email
  • HR: jd-writer / interview-question-gen / candidate-screener
  • Sales: follow-up-email / proposal-drafter / objection-handler
BƯỚC 02 / 06 — SCOPE (description)

Skill kích hoạt khi nào?

Vì sao quan trọng: Đây là trường description — quyết định AI có tự động dùng Skill hay không. Mô tả mơ hồ là sai lầm #1 khiến Skill không bao giờ chạy.
Công thức description tốt
  • [Việc cụ thể] + [Đối tượng] + "Dùng khi..." + [trigger keywords]
  • Tránh: "Giúp về X", "Hỗ trợ Y", "Làm Z dễ dàng hơn"
  • Nên có 2-3 keyword cụ thể user thường dùng
BƯỚC 03 / 06 — PERSONA

AI đóng vai ai?

Vì sao quan trọng: Persona càng cụ thể (vai trò + chuyên môn + đối tượng) thì giọng văn và độ chính xác càng cao.
3 yếu tố cần có
  • Vai trò: "Bạn là [chức danh + năm kinh nghiệm]"
  • Chuyên môn: "Chuyên về [domain cụ thể]"
  • Đối tượng: "Phục vụ [ai], tại [đâu/môi trường nào]"
BƯỚC 04 / 06 — ACTION (workflow)

Quy trình từng bước là gì?

Vì sao quan trọng: Skill khác Prompt ở chỗ có nhiều bước có thứ tự. Mỗi dòng 1 bước, bắt đầu bằng động từ. AI sẽ làm theo đúng tuần tự.
Động từ thường dùng
  • Phân tích / Đọc / Quét / Kiểm tra / Xác định
  • Tạo / Viết / Soạn / Generate / Draft
  • So sánh / Đánh giá / Đề xuất / Tóm tắt
BƯỚC 05 / 06 — RULES (MUST / MUST NOT)

Bắt buộc & cấm kỵ

Vì sao quan trọng: MUST đảm bảo output đúng định dạng. MUST NOT ngăn AI mắc sai lầm phổ biến. Tách 2 list rõ ràng để AI dễ tuân theo.
BƯỚC 06 / 06 — KNOWLEDGE

Đính kèm ví dụ (tùy chọn)

Vì sao quan trọng: Few-shot example giúp AI bắt chước chính xác hơn 10 lần so với mô tả. 1 example tốt > 10 dòng instruction.
Tip viết example tốt
  • Input cụ thể, có dữ liệu giả lập thực tế
  • Output mẫu thể hiện đúng giọng + định dạng mong muốn
  • Có thể skip bước này — nhưng có example sẽ tốt hơn nhiều

SKILL.md của bạn đây 🎉

Copy file dưới và làm theo hướng dẫn cài đặt để Skill tự động chạy trong Antigravity / Claude Code / Cursor.

skill-name/SKILL.md

📦 Cách cài đặt vào Antigravity

  1. Tạo folder với tên Skill: ~/.gemini/antigravity/skills/skill-name/
  2. Tạo file SKILL.md bên trong folder đó
  3. Paste nội dung đã copy ở trên
  4. Restart Antigravity (Skill được scan khi khởi động)
  5. Test bằng cách chat một yêu cầu khớp với description

// Hoạt động tương tự với Claude Code (~/.claude/skills/) và Cursor (.cursor/skills/)

🔧 Khi nào nên chỉnh sửa Skill

  1. Skill không tự kích hoạt → sửa description cụ thể hơn
  2. Output sai giọng → bổ sung Persona
  3. Output thiếu bước → thêm vào Workflow
  4. AI làm sai chỗ nào đó liên tục → thêm vào MUST NOT
  5. Output không đúng format → thêm Example
